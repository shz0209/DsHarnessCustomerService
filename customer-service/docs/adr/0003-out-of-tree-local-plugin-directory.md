# 全部代码放在仓库内的本地插件目录

客服系统的全部代码放在 `customer-service/`，通过一个 `--patch` 覆盖层加载，不修改 `packages/` 下的任何一行。

理由：这些是垂直业务能力，不是 harness 自身的能力。放进 `packages/` 会让每一次改动都背上仓库一等公民的门禁——每文件 100% 覆盖率、双语 i18n、记录快照、跨文件重复代码检测。代价是与 harness 的集成依靠约定（加载行的名字与路径、槽位名、包的 `dsh.client` 声明）而非类型系统保证，升级 harness 时需要人工核对这几处约定。日后若要把这套东西作为产品发布，再迁移进 `packages/`。
