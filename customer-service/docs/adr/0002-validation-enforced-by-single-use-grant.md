# 校验在代码层以一次性凭证强制

「人工还宝」与「退款」在执行前必须先通过对应的校验，这条规则由**一次性凭证**在代码层强制，而不是仅写进系统提示词。校验通过时签发凭证（绑定客户、订单号、动作、会话与签发时间），动作工具在没有有效凭证时拒绝执行；凭证一次性使用、十分钟过期、订单一经变更即失效。

理由：这套系统的演示价值正在于「固定规则必然被执行」。若规则只活在提示词里，模型只要跳过一次，规则就形同虚设。校验本身没有副作用、随时可以重跑，因此强制不会把对话卡死——校验失败后模型仍可重新校验或改走别的路径。

## Considered Options

- **只靠提示词**：实现最省事，但规则可被模型跳步绕过，演示时一旦发生就失去说服力。
- **把校验与动作合并成一个工具**：结构上无法绕过，但校验在业务上是独立的一步（客服先判断能不能办，再决定办不办），合并会让工具返回值同时承担"判定"和"执行结果"两种含义，也让"校验通过后隔一会儿再执行"这类真实节奏无法表达。
