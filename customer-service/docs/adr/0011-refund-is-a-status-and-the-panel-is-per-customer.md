# 已退款是一条订单状态；管理面板面向每个客户自己的订单

两条决定，都由 issue #9 的评审推翻前案，记在这里而不是悄悄改掉：

**一、退款不再只是标记，而是订单状态的第三步。** 订单状态从「进行中 / 已归还」两个变成三个：`进行中` → `已归还` → `已退款`，退款把一笔「已归还」的订单推到「已退款」，并记下退款时间。校验规则随之变成三步判定，顺序固定：**先看是不是「进行中」**（是 → 不允许，充电宝还没还）；**再看是不是「已退款」**（是 → 不允许，不能重复退款）；**最后才看「已归还」与会员等级**（铂金或黑金 → 允许，其余 → 不允许）。因此「已退款」这句话现在由**状态**承载，卡片上不再另挂「已退款」徽章，`orderLine` 也不再追加那三个字。

- 这**推翻 [ADR-0010](0010-service-actions-share-one-validation-pair.md) 里「规则里没有『已退款』这一条」**：那条规则当初是刻意的——已退款的订单再问一次，校验仍然说「允许退款」，退款时间被改写一次。现在它是一句明确的拒绝（「不允许退款，该订单已退款」），重复退款不可能发生。
- 它也**推翻 issue #1 里「退款不是状态，而是订单上的独立标记」**，以及 [CONTEXT.md](../../CONTEXT.md) 中「退款不改变订单状态」的那几条定义；术语表已按新模型改写。
- `退款时间`（`refundedAt`）**保留**：状态说的是钱回没回，时间说的是什么时候回的，两者都要。
- 人工还宝的规则跟着改口径：**只要不是「进行中」就拒绝**，回绝时按订单真实所处的状态说话——「已归还」的仍答「不允许人工还宝，该订单已归还」，「已退款」的答「不允许人工还宝，该订单已退款」，不再把后者说成前一种。
- 演示库里的旧数据由 store 在打开时**单向带正**：带着 `refundedAt` 却仍写着 `returned` 的行改成 `refunded`。这一对取值不可能由新代码写出，读法唯一，所以不需要版本号或迁移开关。

**二、管理面板不再只属于管理员，也不再挂在侧栏。** 它现在是对话区「对话 / 轨迹」那一行右侧的第三个视图（`conversation.view` 槽位，`order: 20`），**每个登录客户都能进**，看到的是**自己名下**的全部订单与状态，可以在面板里创建新订单（填写租借地点、金额、租借时间，订单号与「进行中」状态由服务端决定），也可以把一笔「进行中」的订单**归还**。这**推翻 issue #9 的验收条件**「仅 Administrator 在侧栏看到『管理』入口」与「服务端对每个管理操作再次校验 `isAdmin`」：面板不再是后台，而是客户自助的数据准备口。

权限模型因此更简单而不是更弱：**所有面板路由都按登录态取 `customerId`，请求体里根本没有客户字段**，别人的订单号在面板里是「不存在」而不是「被拒绝」——与五个工具完全同一条隔离规则（[ADR-0004](0004-customer-identity-from-login-not-parameter.md)）。「所有人都能创建订单」之所以可以接受，正是因为创建的只能是**自己**的订单，演示者换一个账号登录即可为那个账号造数据。

## Considered Options

**状态一：**

- **保留标记、只加校验规则。** 卡片与文案都得同时表达「钱退了」和「物还没/已还」，模型也要同时读两个字段才能判断能不能再退；用户明确要求状态里有「已退款」这一项，采纳它反而让规则只有一处判断。
- **把已退款做成「已归还」上的第四种取值。** 退款发生在归还之后，是一个更靠后的阶段，不是平行的另一种归还；顺序表达得出来，取值就按顺序排。

**状态二：**

- **面板留在侧栏，只放宽可见性。** 侧栏是账号与身份的地方，面板是订单的地方；「对话 / 轨迹」那一行本来就是「换个视角看本次会话」的位置，多一个视图比在侧栏里塞一个入口更顺。
- **管理员保留「替任意客户造单」的能力。** 那需要请求体里带客户字段，于是同一条隔离规则要在面板里再写一遍（校验它等于当前登录客户）；让每个人只造自己的单，规则就只有登录态一个来源。演示者换账号登录即可。

## 后果

- **演示「允许人工还宝」那一侧不再需要管理员账号。** 用任一个账号登录，在管理面板里造一笔「刚借出」的订单，回到对话问一句即可；造一笔租借时间在三小时前的，就是拒绝的那一侧。
- 面板的「归还」按钮**不走校验、不签发凭证**：校验与凭证是为了拦住**模型**在规则没跑的情况下动手（ADR-0002），面板不是模型，写的是客户自己的行。模型也够不到这些路由——它能调的仍然只有五个工具（ADR-0005）。
- 面板的写入是直接改库，所以它**能让一笔超过两小时的订单变成「已归还」**。这是演示工具与本项目服务动作之间的已知差异，界面上以「管理」这个视图名区分，不假装它是客户服务的一部分。
- 侧栏不再有「管理」入口，管理员身份仍由侧栏徽章与注入模型的身份行表达；issue #9 里那条「管理员账号同样受工具白名单限制」的验收仍然成立，并且仍由 `tests/panel.spec.ts` 覆盖。
