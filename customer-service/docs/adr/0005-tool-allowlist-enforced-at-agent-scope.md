# 工具白名单在 agent 作用域强制

客服 agent 只能看到并调用那 5 个业务工具，其余一律不可用。实现方式是在 agent 作用域上施加工具白名单（`tools.restrict({ allow })`，必要时叠加一个 guard 作为第二道防线），而不是靠"不加载其它的工具插件"。

## Considered Options

- **只不加载其它工具行。** 表面上最省事，但做不到完整：有些工具注册在宿主层，不对应任何可禁用的加载行（例如 `working_directory`），白名单之外总会有漏网的。而且它对"以后新增的工具行"没有免疫力——新装一个 bundle，工具就重新开放了。
- **在系统提示词组装阶段增删工具。** 仓库自己的文档明确劝阻这种做法，因为那条路径绕开了工具列表与调用派发共用的解析器，会让"藏起来"和"调不动"脱钩。

选择作用域白名单的理由：工具列表、按名字查找、调用派发三者共用同一个解析器，所以白名单是**真正强制**的，而不是伪装。代价有两点——限制必须从一个比工具更深的作用域施加（agent 作用域），且白名单里的名字必须已经在祖先作用域注册完毕，否则启动即报错；这个报错是我们要的：配置错了就响亮地失败，绝不静默放开。

另有一处保留名：PTC 模式下的 `run_code` 是传输层而非能力，无法被白名单排除，因此必须保持 native 模式（仓库默认即 native）。
