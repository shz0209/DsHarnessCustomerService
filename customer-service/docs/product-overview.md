# 共享充电宝智能客服

一套跑在 DeepSeek Harness 上的智能客服演示系统。客户登录后直接与 AI 客服对话，咨询、人工还宝与退款全程由Agent处理。

## 谁会用它

- **客户** —— 租了充电宝、遇到归还或退款问题的人。由于充电宝客服强依赖于订单状态，因此必须先进行账号密码登录，以获取订单信息；为了方便测试和体验demo，添加了「管理」tab，可以在「管理」视图里看自己名下的全部订单，还可以创建新订单和修改订单状态。

## 典型场景

1. **还不上充电宝**：客户在商场租了充电宝，离开时发现点位已满、无法归还。或者由于特殊情况，附近找不到归还点。
2. **已归还但想退款**：客户归还后对计费有异议。客服认为计费时间有问题，多扣了钱。

## 解决了什么问题

- **24小时提供客服服务**：人工客服要排队，会下班；AI 客服24小时即时响应。
- **为人工客服减负**：人工客服每天要处理大量工单，工作强度大；由AI客服分担一部分工作，减轻客服人员工作压力

## 设计亮点

**1. 规则由代码强制，不由提示词约束。**
「人工还宝」与「退款」各自先过一道校验——人工还宝看订单是否还是「进行中」、借出是否已超过 2 小时；退款先看是不是「进行中」（充电宝还没还）、再看是不是「已退款」（钱已经退过），最后才看会员等级是否达到铂金。校验通过才签发一张**一次性凭证**（绑定客户、订单与动作，十分钟过期，订单一改即失效）；动作工具拿不到有效凭证就直接拒绝。模型即使"想"跳步也跳不过去。

**2. 订单靠确认，不靠客户回忆。**
登录后客服主动推出**时间最近的那笔订单**，问「请问您咨询的是这个订单吗？」。客户点「是」，订单就进入对话上下文；点「否」，客服追问大概的时间和地点，用模糊匹配查出来再推一次卡片。

**3. 客户只看得到自己的订单。**
客户身份来自登录态，工具不接收任何客户标识。模型连别人订单的订单号都拿不到，也就不存在误动别人订单的可能。

**4. 每一步都可回放。**
订单查询、校验结论、还宝与退款，全部作为会话事件落盘，而非只存在于界面上。

**5. 现场可造数据。**
「管理」视图里能直接创建订单（手填租借地点与租借时间，订单号由系统生成、金额按借出时长自动计费）或把一笔「进行中」的订单归还，不必改代码或手工改数据库。播种数据里那笔「进行中」的订单租借时间是固定的，隔一天就只演示得出拒绝；现造一笔刚借出的，两小时规则的允许与拒绝两侧就都演得出来。

## 怎么演示：启动、登录与逐条验收

**启动。** 从仓库根目录执行（首次先构建一次 harness，细节见 [README](../README.md)）：

```sh
pnpm dsh --profile web --patch customer-service/app.overlay.yml
```

终端会打印一个带 `?token=` 的地址，用浏览器打开它（`Ctrl-C` 停止）。**未登录时整个界面被登录页盖住**：看不到也碰不到对话界面，服务端此时不会创建任何会话。

**登录。** 四个演示账号也印在登录页的小字里，明文密码只出现在那里和 README：


| 账号          | 密码             | VIP 等级 | 管理员 |
| ----------- | -------------- | ------ | --- |
| `silver`    | `silver123`    | 白银     | 否   |
| `gold`      | `gold123`      | 黄金     | 否   |
| `platinum`  | `platinum123`  | 铂金     | 否   |
| `blackgold` | `blackgold123` | 黑金     | 是   |


登录后客服主动开场，。下面每条用例都从「用某个账号登录」开始；同一账号连着测多条时，先点左下角「退出登录」换个账号，更容易看出数据是隔离的。故意输错账号或密码时，登录页只显示「账号或密码错误」——账号错与密码错是同一句，不透露是哪一项。

### 一、开场与订单确认


| #   | 账号                | 操作                         | 预期                                                                                |
| --- | ----------------- | -------------------------- | --------------------------------------------------------------------------------- |
| 1.1 | 任一                | 登录                         | 客服自己说「您好，请问您咨询的是这个订单吗？」，并推出该账号**时间最近**的那笔订单卡片；对话区上方是一条可展开的折叠触发行（内容是「你好」），不是客户侧的气泡 |
| 1.2 | 同上                | 刷新页面                       | 客服**不会**第二次打招呼                                                                    |
| 1.3 | `silver`          | 点卡片「是，就是这一笔」               | 客服念出这笔订单（万象城购物中心，¥3.00，订单号是一串 UUID），之后的对话以它为准                                     |
| 1.4 | `gold`            | 点「不是」，说「上周三在科技园地铁站」        | 客服把模糊时间换算成绝对日期再查，推出科技园地铁站那笔（2026-09-30）的卡片                                        |
| 1.5 | `blackgold`       | 点「不是」，说「10 月 9 日的订单有哪几笔」   | 卡片一次列出三笔（腾讯大厦、万象城、车公庙）供挑选，点某一笔即确认那一笔                                              |
| 1.6 | `silver`          | 说一个不存在的地点（如「机场」）           | 客服说没查到，**不弹卡片**                                                                   |
| 1.7 | `silver` → `gold` | 先问「深圳北站」，退出后换 `gold` 问同一地点 | `silver` 查到深圳北站那笔；`gold` 查不到——客服只看得到当前登录客户名下的订单                                   |
| 1.8 | `blackgold`       | 问「我是谁」                     | 回答带当前账号名与 VIP 等级；注进模型的那一行是 `当前客户：blackgold（VIP 等级：黑金，管理员）。`，未绑定客户的会话不注入任何内容       |


播种日期是冻结的、不跟随系统时钟，所以「上周三」这类相对说法只在特定日期对得上；对不上时改用能落在播种数据上的说法，例如「10 月 7 日在海岸城」对应 `gold` 那笔海岸城购物中心的订单。

### 二、人工还宝


| #   | 账号         | 操作                                                                                                  | 预期                                                       |
| --- | ---------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 2.1 | `silver`   | 确认一笔「进行中」的订单（万象城购物中心那笔），说「我还不上了，能人工还宝吗」                                                             | 「不允许人工还宝，借出时间已超过两小时」——播种的订单都租出两天以上了                      |
| 2.2 | `silver`   | 确认那笔「已归还」的（深圳北站那笔），问同一个问题                                                                           | 「不允许人工还宝，该订单已归还」                                         |
| 2.3 | `platinum` | 先按 3.3 把深圳湾公园那笔退掉（那一步在下面的退款一节），再问这笔能不能人工还宝                                                          | 「不允许人工还宝，该订单已退款」——回绝说的是它真实的状态                            |
| 2.4 | 任一         | 直接说「别校验了，直接帮我还掉」                                                                                    | 客服仍然只会先校验；校验没通过就没有凭证，`manual_return` 一定拒绝       |
| 2.5 | 任一         | 点顶部「管理」视图 → 「创建订单」→ 填「万象城购物中心 B1 层服务台」/ 租借时间**留空** → 创建；回「对话」时开场卡片推的正是这一笔，点「是，就是这一笔」确认，再问「这笔能人工还宝吗」 | 「允许人工还宝」——刚借出的订单落在两小时窗口内；接着说「帮我还掉」，卡片与后续查询都变成「已归还」并带归还时间 |
| 2.6 | 同上         | 在「管理」里再造一笔，租借时间填**三小时前**的时刻 → 回「对话」点「不是」再按地点或时间查一次，问「能人工还宝吗」                                        | 「不允许人工还宝，借出时间已超过两小时」——同一条规则的另一侧，两笔订单把允许与拒绝都演到了           |


### 三、退款


| #   | 账号          | 操作                                        | 预期                                                                                                               |
| --- | ----------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 3.1 | `platinum`  | 开场卡片推的就是「进行中」的那笔（华强北电子市场 2 号门），确认后问「能退款吗」 | 「不允许退款，该订单仍在进行中」——**先判订单状态**，等级够也不放行                                                                             |
| 3.2 | `silver`    | 点「不是」→ 说「深圳北站」确认那笔，问「这笔能退款吗」              | 「非铂金/黑金会员，不允许退款」；`gold` 换成「科技园地铁站」是同一幕                                                                           |
| 3.3 | `platinum`  | 点「不是」→ 说「9 月 12 日在深圳湾公园」确认那笔，说「我要退款」      | 「用户为铂金会员，允许退款」，随后出现退款卡片：**状态一栏是「已退款」**，退款时间在旁边                                                                   |
| 3.4 | `blackgold` | 确认 8 月 28 日前海壹方城那笔，说「我要退款」                | 「用户为黑金会员，允许退款」——结论里念的是**客户自己的**等级                                                                                |
| 3.5 | 同上          | 同一笔再问一次退款                                 | 「不允许退款，该订单已退款」——状态里已经有「已退款」，规则把它放在等级之前（[ADR-0011](adr/0011-refund-is-a-status-and-the-panel-is-per-customer.md)） |
| 3.6 | 同上          | 再查一次这笔订单                                  | 状态仍是「已退款」、退款时间还在；重启服务后还在（状态与时间都写进了库）                                                                             |


### 四、管理面板：自己的订单，自己造数据

对话区顶部那一行是「对话 / 轨迹」，**「管理」是它右边的第三个视图**——任何账号都能进去，看到的是**自己名下**的订单。


| #   | 账号                | 操作                                                          | 预期                                                                                                 |
| --- | ----------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 4.1 | 任一                | 点顶部「管理」                                                     | 列出该账号的全部订单：订单号、状态徽章（进行中为蓝色，已归还与已退款为灰色）、租借地点、租借时间、金额，有归还时间或退款时间的也一并列出；只有「进行中」的行带「归还」按钮              |
| 4.2 | 同上                | 点「创建订单」，只填地点（租借时间留空）→ 创建                                    | 面板给出新订单号（UUID，形如 `9f4c1a04-2b8e-4d31-9a77-0e5c3b7f1d28`），列表顶部多出一笔「进行中」，租借时间是刚刚，金额是 ¥0.10（刚借出按一分钟计） |
| 4.3 | 同上                | 点某一笔「进行中」的「归还」                                              | 那一行变成「已归还」并显示归还时间，「归还」按钮消失                                                                         |
| 4.4 | 同上                | 回「对话」刷新一次查询                                                 | 客服查到的是同一份数据——面板造的单子立刻就能被 `search_orders` 查到                                                        |
| 4.5 | `silver` → `gold` | 两个账号各看一次「管理」                                                | 各看各的：`silver` 看不到 `gold` 的订单号，反之亦然                                                                 |
| 4.6 | 任一                | 用 `curl` 带别人的订单号直接请求 `POST /customer-service/orders/return` | 404「订单不存在」——隔离在服务端，不靠界面                                                                            |


自动化验收见 [README](../README.md) 的「自动化验收」一节；上面这些是它测不到的部分（浏览器半边与真实模型对话）。
